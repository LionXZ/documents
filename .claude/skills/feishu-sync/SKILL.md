# 同步文档到飞书知识库

把本仓库的 Markdown 文档按目录结构同步到飞书知识库。同步是**镜像语义**：
新增/修改的文档会上传，本地已删除的文档会同步删除远端。

## 前置检查（每次执行前）

1. 确认仓库根目录存在 `.env`，且包含 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_SPACE_ID` 三项。
   不存在则**停止**，提示用户参照 `.env.example` 创建。凭证绝不写入任何会入库的文件。
2. 确认 `scripts/sync-to-feishu.mjs` 存在。

## 执行

在仓库根目录运行（用户没提特殊要求时的默认命令）：

```bash
node scripts/sync-to-feishu.mjs --changed
```

可选参数（仅用户明确要求时叠加）：

- `--dry-run`：只列出将要新增/更新/删除的清单，不调任何写接口
- `--force`：忽略内容 hash 全量重传（远端文档全部重建，消耗约 600 次 API，慎用）

## 汇报

运行结束后向用户报告：

- 新增/更新/删除的文件清单（逐条相对路径）
- 跳过数与失败数；有失败则列出文件名与原因
- API 消耗（免费额度 10,000 次/月，超出需充值）
- 全部成功时会显示 HEAD 已推进；下次只同步新的差异

## 常见情况处理

| 现象 | 处理 |
| --- | --- |
| `未找到 .env` | 引导用户复制 `.env.example` 并填入凭证，不要代填 |
| `需同步 0 篇` | 告知用户自上次同步后没有文档变更 |
| 单篇失败 | 报告失败清单；说明下次执行会自动重试（HEAD 只在全部成功时推进） |
| token 获取失败 | 多为 App Secret 被重置后 `.env` 未同步更新，引导用户核对 |
| 提示未找到可用的上次 HEAD | 正常降级：本次会全量比对内容（未变的不上传），完成后记录 HEAD |

## 注意

- `.feishu-sync-map.json` 是同步状态文件（路径→节点映射、内容 hash、上次同步的 git HEAD），**不要手动编辑**；更换目标知识库时删除它后重跑。
- 不要把 `.env` 提交进 git。
